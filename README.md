# Xbox2Windows

**[Join the Xbox2Windows Dev Discord](https://discord.gg/DMcmNtpd6R)** · [Project status](#current-results-and-open-work) · [Get involved](#community-and-contributions) · [Build on Windows](#first-build) · [Run the GPU check](#run-the-gpu-check)

Xbox2Windows researches static recompilation from Xbox Series X|S (Scarlett) to x64 Windows. It translates selected x64 machine code into C++ and selected gfx1013 shaders into desktop DXIL. You can run the public tests without a game installation.

> **Startup.** On an RTX 4060 Laptop, a modified diagnostic EXE with automatic assertion continuation played the intro, displayed readable setup text and reached loading. Startup of the original EXE, main-menu navigation and gameplay remain unverified. [Progress and current blockers #870](https://github.com/R0Y00/Xbox2Windows/issues/870) · [RX 9070 XT report](https://github.com/R0Y00/Xbox2Windows/pull/1135) · [GPU tasks #874](https://github.com/R0Y00/Xbox2Windows/issues/874)
>
> **Static recompilation.** A source-built EXE reads two compressed BC7 texture pages and draws them. Native Windows, mapped PE and AOT builds produced identical pixels on RTX 4060 Laptop and WARP. [Archive-to-draw test #1331](https://github.com/R0Y00/Xbox2Windows/pull/1331)
>
> **Shader compilation.** The full-package scan found a DXIL compilation route for 26,500 of 26,503 shader records.

## First build

On x64 Windows, install Python 3.11 or newer and Visual Studio's **Desktop development with C++** workload, including x64 MSVC, CMake, Ninja, and the Windows SDK with DXC. Windows CI uses Python 3.12.

Use Windows SDK 10.0.26100 for new installations. A contributor using SDK 10.0.22621.0, MSVC 19.44 and the bundled DXC 1.6.2112.16 [completed `cmake --build --preset dev`](https://github.com/R0Y00/Xbox2Windows/pull/1369). In that run, `dxc_compile_time_gvn` failed because DXC reported `-ftime-report` as an unknown argument. The test now [returns 77 for that diagnostic](https://github.com/R0Y00/Xbox2Windows/pull/1393), so CTest reports it as skipped. See [Windows build notes](#windows-build-notes) to select a different DXC.

Visual Studio 2019 Build Tools (MSVC 14.29) build every target except the five CRT-free TLS EXE fixtures (`cpu_exe_tls*`), because that compiler leaves their thread-local initializers to the C runtime. For the same reason `cpu_native_tls_value` fails there, `cpu_package_main_image` lacks its fixture, and `xmem_attribute_scan` also sees the unused delay-load jump thunk that the 14.29 linker emits. Open PowerShell and run the following commands. If you already have a clone, start at `.\tools\dev.ps1`.

```powershell
git clone https://github.com/R0Y00/Xbox2Windows.git
cd Xbox2Windows
.\tools\dev.ps1
python -m venv out/pe-env
.\out\pe-env\Scripts\python.exe -m pip install -r requirements-dev.txt
cmake --preset dev
cmake --build --preset dev
ctest --preset dev --no-tests=error -R 'desktop_root_signature|era_heap_allocation|offscreen_warp'
```

The smoke tests exercise a D3D12 root signature, heap allocation and software rendering. For just those checks, you can omit the two Python setup commands. With the Python environment installed, [run a focused experiment](#choose-an-experiment) or run the full suite with `ctest --preset dev --no-tests=error`.

To build and test at /O2 as Windows CI also does, use the `release` preset in place of `dev`. Its build directory is `out/build/release`.

Contributing from macOS or Linux? See the [non-Windows host guide](docs/non-windows-hosts.md) for the platform-independent Python and LLVM 15 checks.

**Inspect a source-built PE package offline:** `python -B tools/pe_package_preflight.py
out/source-built-package app.exe --output out/pe-package-report.json` reports direct/delay
imports, package export/forwarder closure and external providers that could not be
verified on the host, without loading an EXE or DLL. [Scope and synthetic tests](docs/experiments.md#offline-package-pe-import-closure).

**Inspect one AMD64 PE image's import routing offline:** `python -B tools/compat_report.py <image.exe> --json out/compat-report.json --markdown out/compat-report.md` labels each normal and delay import as a candidate HLE, Windows, stub or unsupported module route from an explicit policy; the labels do not resolve exports or prove a provider. It also reports TLS, SEH and load-config directory presence. It reads the image without loading or executing it. This is an offline routing report, not a runtime measurement.

### Windows build notes

- **DXC validation.** `shader_metadata_probe` skips when the validator lacks module-only validation. DXC 1.8.2502 is the first verified release that passes. A DXC that ships no separate `dxil.dll`, such as the 1.9.2602.17 of a later SDK servicing update, is validated through `dxcompiler.dll`. To use a separate DXC installation, configure with `cmake --preset dev -DDXC_EXECUTABLE=C:/path/to/dxc/bin/x64/dxc.exe`. [Results by release](docs/experiments.md#module-only-validation-by-dxc-release) · [Original report](https://github.com/R0Y00/Xbox2Windows/issues/98) · [DXC download](https://github.com/microsoft/DirectXShaderCompiler/releases/tag/v1.8.2502)
- **Windows 10.** The source-built BVH buffer operations run on in-box WARP at SM 6.0. For WARP checks that require SM 6.5 or DXR, use the app-local Agility SDK and WARP packages. [BVH buffer operations](docs/experiments.md#bvh-buffer-operations-on-in-box-warp) · [Windows 10 setup](docs/experiments.md#windows-10-with-the-app-local-agility-sdk-and-warp)
- **Path length.** Clone to a short path such as `C:\Users\<name>\Documents\Xbox2Windows`. In a checkout about 150 characters deep, CMake's compiler check fails with MSVC error C1041 because the object paths under `out/build/dev` pass the 260-character limit.
- **Independent build.** A Windows 11 contributor reproduced the three smoke tests from a clean checkout at `71bb9f4` and again after an incremental rebuild at `2465837`. [Toolchain, full-suite results and capability skips](https://github.com/R0Y00/Xbox2Windows/issues/2#issuecomment-7063351821)
- **Zig cache.** The two Zig fixtures are built by `python -m ziglang build-exe`. If that step stops the build with `error: AccessDenied`, point both Zig caches at writable directories before configuring: `$env:ZIG_GLOBAL_CACHE_DIR = 'out/zig-global'` and `$env:ZIG_LOCAL_CACHE_DIR = 'out/zig-local'`. [Reproduction and measured before/after](docs/experiments.md#two-record-archive-reader-from-standard-startup)
- **Carrier temp directory.** The TLS and `exe_aot_convert` fixtures create their carrier under `GetTempPathW`. If they fail with `cannot create the TLS carrier directory (error 5)`, that directory is not writable for the built executables on that host: set `TMP` and `TEMP` to a writable directory before running them. [Measured case](docs/experiments.md#tls-callbacks-and-the-entry-point)
- **Fresh shell.** `.\tools\dev.ps1` enters the Visual Studio developer environment, which changes only the current PowerShell session. Run it in each new PowerShell session before building or testing. If `ctest` or the other tools supplied by Visual Studio are missing from `PATH`, rerun the script in that window.

## Run the GPU check

Download the [Windows x64 GPU check and SHA-256](https://github.com/R0Y00/Xbox2Windows/releases/tag/gpu-check-v0.1.0), verify and extract the ZIP, then run this in PowerShell from the extracted folder. The package contains its own shaders and needs no compiler, console or game files.

```powershell
.\Run-GpuCheck.ps1
```

With a package built from current source, use `.\Run-GpuCheck.ps1 -Adapter Radeon` to select a hardware adapter by part of its name. For source builds, set `XBOX2WINDOWS_ADAPTER` before running CTest.

Review `gpu-report-hardware.md` and paste its full contents as a comment on the [hardware coverage thread (#1)](https://github.com/R0Y00/Xbox2Windows/issues/1). Do not open a new GitHub issue. Reports with a failure or capability skip are welcome. [Package instructions](tools/gpu-check/README.md)

## Case study and provenance

The installation metadata inspected for this case study lists a Scarlett executable. The main executable was absent from the inspected files. The public regression suite uses source-built fixtures and independently built shaders. [Intake methods and evidence](docs/experiments.md#static-executable-intake)

Windows Authenticode verification on the local copy reported `HashMismatch` for 12 DLLs and `NotSigned` for four. Three independently compared whole-file SHA-256 values matched the community reports. The cause of the digest mismatch and the original signing path remain undetermined. [Methods and fingerprints](https://github.com/R0Y00/Xbox2Windows/issues/52) · `tools/pe_authentihash.py` recomputes the Authenticode SHA-256 digest of a PE file; `tests/pe_authentihash_check.py` checks it on self-built PE32 and PE32+ files against digests from the Windows API.

XCL is a public behavioural reference for what a retail title may ask of the platform. The [XCL reference](docs/xcl-reference.md) records the GPL-2.0-only boundary and the pinned revision; the [capability matrix](docs/xcl-capability-matrix.md) maps selected XCL behaviours to named checked-in tests. Neither document is an Xbox2Windows measurement or a roadmap.
